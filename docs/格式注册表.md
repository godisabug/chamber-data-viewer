# 文件格式注册表

## 多选合并语义

* 仅限同一文件夹、全部为同一格式；跨文件夹或混用格式整组拒绝。
* 按正文时间确定性合并，选择顺序不影响结果；相同时间点且各通道值完全相同去重，任一无值/有值差异整组拒绝。
* 采样周期按内容推断（阿泰可各格式 30 秒、汉测 60 秒），相邻真实采样间隔超过周期 + 5% 容差视为停录间断，每个间断插入一个 `null` 断点并汇总缺失槽数。
* 文件边界处若下一文件首个采样不在周期网格上（例如汉测两段记录间隔 36 秒、周期 60 秒），视为重新开始的一段记录，强制插入断点；同网格的连续导出（如按天截断、跨日间隔恰为一个周期）不插断点。

## ZIP 容器与解压文件

* 弗锐德两种导出均为 ZIP 容器（`.HSHBKA` / MData zip）。用户可能以三种方式打开同一份数据，三者都必须可用：
  1. 直接打开 ZIP 容器文件（按容器规则解析内部 CSV）；
  2. 打开解压后的内部 CSV（`s1_history.csv` / `history_data.csv`，按独立 CSV 规则解析）；
  3. Windows 11 将 ZIP 视为文件夹，用户在资源管理器或文件对话框中直接选中 zip 内部的 CSV（应用收到 `xxx.HSHBKA\s1_history.csv` 形式的虚拟路径，按压缩成员解析）。
* 容器规则与内部 CSV 规则是两种格式 ID，但通道定义相同；多选合并仍要求同一文件夹、全部同一格式。

## 新增格式流程

新增解析器前必须先在本表登记，再按以下模板实施：

1. 登记格式条目：结构特征、编码、列/通道定义、缺失值语义、支持状态；
2. 实现内容探测 `probe`（必须与现有规则互斥，不按扩展名判定）；
3. 实现解析 `parse` 与规则元数据；
4. 提供最小化合成夹具与真实样本回归（真实样本留在本地，不入库）；
5. 运行全量验证，提交推送，重新构建 EXE 并做桌面验收；
6. 在本表中把支持状态改为“已支持”，补记验证记录。

## 规则 ID 语义

* 规则 ID 表示**格式与版本**，例如 `weintek-export-v1`，不绑定试验箱厂家或具体设备。
* 规则只描述格式本身（探测、解析、通道与坐标轴），不携带控制器或设备身份，软件也不展示设备身份。
* 同一格式出现在新设备上时，不新建或改名规则。

## 零值语义（0 = 未控制/未设置）

部分控制器的导出文件在通道“未控制/未设置”时把设定值写为 0（而不是缺失哨兵），常见于湿度设定，温湿高箱的气压/高度设定同样如此。为避免把“未控制”画成 0 值贴底线，统一按以下规则处理：

* **湿度设定、气压设定通道**：数值为 0 时按缺失数据处理（曲线断开），并在全序列均为 0 时不生成该曲线（如宝元通、三志样本的湿度设定）。
* **温度设定通道**：0 ℃ 是合法试验设定值，不适用该规则。
* **实测通道（PV）**：0 是真实读数，不适用该规则。
* 适用格式：`utf8-11col-hmi-csv`、`16bit-7col-csv`、`weintek-export`、`kr-tsv`、`kr-rcd-bin`、`atec-6col-csv`、`mcgs-5col-csv`、`freud-s1-history-csv`、`freud-hshbka`、`freud-history-csv`、`freud-mdata-zip`、`samwontech-temi2500-sdr`、`guangwusuo-000`、`csv-standard`（兜底）。
* 该语义在规则中显式声明（`zero_as_missing`），不依赖隐式猜测；后续新增格式时若导出方以 0 表示未控制，应在登记格式时一并声明。

## 纵轴数量与布局

* 数据集支持 1 至 3 条纵坐标轴：1 条主坐标轴（左）+ 最多 2 条次坐标轴（右）。
* 温湿高箱采用三纵轴：主轴温度（左）、次轴气压（右，贴绘图区）、次轴湿度（右，偏移一列），各自独立单位、量程与手动范围；气压为高权重特征量，优先占贴边槽位。
* 仅三轴数据集的右侧绘图边距加宽以容纳第二列次轴；双轴数据集布局保持不变。
